正式文档开始。

【条目 01】课题组正在准备毕业答辩，需要录制一个 30 秒系统演示视频，展示长文本生成场景下，不同 KV Cache 稀疏策略对远距离信息检索的影响。为了保证实验可复现，录制时不使用随机采样，而是固定使用确定性解码。大家一致认为，这个视频的重点不是看谁打字更快，而是看谁能在长上下文里找回较早位置出现的关键事实。

【条目 02】第一次讨论时，大家列出了几种可选方法：课题组自研方法、H2O、Streaming 方案，以及 Full Attention。考虑到 Full Attention 只是理论上限，不适合作为短视频的主要看点，最终决定只展示三路：Ours、H2O、Streaming。这里的 Streaming 指的是仅保留 sink token 与局部窗口的滑动窗口方案。

【条目 03】老师建议不要使用普通常识问答来录视频，因为常识题即使忽略上下文，模型也可能凭先验知识答对，那样无法证明方法在长文本场景中的真实差异。相比之下，从长记录里检索一个较早位置的唯一关键信息，更能体现不同方法的能力差别。

【条目 04】大家据此设计了一种“长文埋点”方案：在文档中部给出唯一的正式答案，后半部分连续放置若干近距离干扰项。这样，如果某种方法只能看到最近窗口，就更容易被文末噪声吸引；而如果某种方法还能回忆到中部的正式条目，就更可能给出正确结果。

【条目 05】为了让演示更像真实工作记录，而不是像人工拼凑的测试样例，文档里保留了很多无关信息，例如录屏时窗口是否贴边、字幕是否后期加上、终端字体是否需要放大、鼠标高亮是否开启、PPT 页面切换是否加转场等。这些信息在答辩中不会单独讲解，但它们可以增加上下文长度，强化检索难度。

【条目 06】记录整理人还补充了一些和最终答案无关的流程细节：演示视频的开头最好先展示 prompt 已经加载完成；中间三路方法并行或依次生成；最后把三路输出定格到同一画面，并用颜色标出正确和错误。评委不一定会读完整份长文，但他们能立刻看出谁输出了正确字符串。

【条目 07】在更早的筹备版本里，组里出现过几组候选访问码。它们分别被用于临时截图、测试脚本、旧草稿和人工抄录，状态都不相同。有人担心这些历史信息会干扰模型，但老师认为这恰恰是长文本检索任务需要的真实噪声，因此决定保留这些旧记录。

【条目 08】下面是一部分较早期的候选信息，仅用于归档：
- 旧草稿候选：RIVER-4821
- 截图临时码：CEDAR-5530
- 手工误抄码：MAPLE-2718
- 脚本占位码：STONE-2719
这些都不是最终批准版本，只是早期记录中曾经出现过的候选项。

【条目 09】项目负责人强调，真正用于答辩录屏的访问码必须满足三个条件：第一，已经正式写入发布单；第二，已经完成最终核验；第三，必须是唯一有效版本。只满足其中一两个条件的历史候选项，都不能作为最终答案。

【条目 10】以下这条是最重要的正式发布信息，请准确保留：
毕业答辩系统演示视频的发布单已经签字确认。
唯一正式批准并完成最终核验的访问码是：
[FINAL_APPROVED_CODE] MAPLE-2719 [/FINAL_APPROVED_CODE]
只有这个码可以在答辩现场作为正式展示结果使用。

【条目 11】在正式发布信息写入之后，项目组并没有立刻结束讨论，而是继续补充了很多与录屏有关的细枝末节。例如是否把方法名放在终端标题中、是否把命令行字体调成更大号、是否保留 shell 提示符、是否在旁边同步显示“标准答案”小标签等。这些内容会让后面的文本更长，但不会改变已经确认过的正式访问码。

【条目 12】另一个小分歧来自于字幕文案。有人想在视频里说明“本实验考察长文本生成中的远距离信息检索能力”，也有人觉得不如直接显示结果，让评委自己观察差异。最后决定折中处理：视频中只保留很少的文案，把更多解释放到口头答辩里说。

【条目 13】为了增加干扰，记录里故意保留了一张后置汇总表。表中出现的字符串看起来都像有效访问码，但这张表只是为了测试模型会不会被最近的错误候选带偏，并不具有正式发布效力。汇总表的内容如下：

- PINE-4026：另一个无关项目的样例码

【条目 14】后来还有人补充了一段群聊摘要。摘要里有人说：“我印象里最近看到的可能是 MAPLE-2718，或者是 STONE-2719，也可能是 RIVER-4821。” 这段群聊并不可靠，因为它既不是正式发布单，也没有“最终核验通过”的标记，所以只能视为噪声。

【条目 15】项目组还保存了一份错误整理稿，里面写着：
“候选结果列表：RIVER-4821 / CEDAR-5530 / MAPLE-2718 / STONE-2719 / PINE-4026。”
这份整理稿后来被明确标注为“仅作干扰样例，不作为正式答案依据”。虽然它出现在文档靠后位置，但它不能覆盖前面已经签字确认的正式发布信息。

【条目 16】在录屏彩排时，有同学故意只看文档最后几行，结果误把 STONE-2719 当成了正确答案。老师正是基于这个例子，决定把这类干扰项保留在最终 prompt 中。因为如果某种方法在长文本场景下只能依赖最近窗口，就更可能像这位同学一样，只看到最后的候选汇总，而忽略前面真正的正式发布条目。

【条目 17】下面继续补充一些和答案无关的细节：录屏分辨率暂定为 1920x1080；窗口布局可能使用左右分栏，也可能使用上下分栏；视频最后一页 PPT 可能放三路输出截图，也可能直接嵌入短视频；鼠标指针高亮默认关闭。以上细节只是为了拉长上下文，不影响最终答案。
