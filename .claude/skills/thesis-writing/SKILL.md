# 硕士毕业论文书写

## 项目背景

论文研究基于权重敏感度列剪枝与层间蒸馏的 KV Cache 预取框架，核心贡献：
- **敏感度列剪枝**：基于 Top-K 贡献度的特征对分析，构建轻量级预测算子
- **混合稀疏掩码**：融合 Dynamic Top-K + Sink Token + Local Window
- **排序一致性蒸馏**：Pairwise Ranking Loss + 动态负采样
- **混合精度架构**：Int4 预测 - FP16 检索的分级存储

## 持久化状态管理

本 Skill 通过 [thesis_state.md](references/thesis_state.md) 持久化保存所有关键信息，支持跨会话反复使用。

### 状态文件内容
- **参考示例格式特征**：从别人论文提取的格式约束
- **已写章节索引**：用户自己章节的文件路径
- **术语定义表**：全论文术语统一表
- **符号与编号**：公式/图/表编号范围
- **Claim-实验对应表**：理论与实验的映射
- **写作风格备忘**：用户行文特征和偏好
- **书写进度**：各小节完成状态
- **用户反馈记录**：关键决策和反馈

### 状态维护规则
1. **每次会话开始时**：先读取 `references/thesis_state.md`，恢复上下文
2. **触发更新的时机**：
   - 用户上传新的参考示例或已写章节 → 更新对应区块
   - 完成一个小节的书写 → 更新书写进度
   - 用户给出关键反馈或偏好 → 记录到反馈记录和风格备忘
   - 新增术语/公式/图表 → 更新术语表和编号范围
3. **更新方式**：直接编辑 `references/thesis_state.md` 对应区块，不覆盖其他区块

## 交互式书写工作流

### Phase 0: 恢复上下文
1. 读取 [thesis_state.md](references/thesis_state.md)，检查已有状态
2. 如果已有参考示例格式、已写章节、术语表等 → 直接复用，跳过重复提取
3. 如果是首次使用 → 告知用户可以提供参考示例和已写章节

### Phase 1: 确定范围与素材收集
1. 确认用户要书写的章节/小节
2. 读取 [thesis_structure.md](references/thesis_structure.md) 确认章节编号和定位
3. 检查 `thesis_state.md` 中是否已有参考示例和已写章节信息
4. 如果缺少，询问用户是否有以下素材：
   - **参考论文示例**：别人的论文章节（用于仿照格式）
   - **已写章节**：自己已完成的前序章节 md 文件（用于衔接）

### Phase 2: 分析参考示例（如有新上传）
当用户上传了别人的论文章节作为参考示例时：
1. 通读参考示例，提取以下格式特征并向用户确认：
   - **章节层级**：几级标题、编号风格（如 5.1.1 vs 5-1-1）
   - **段落模式**：每节的典型段落结构（如：目的→方法→结果→分析）
   - **图表风格**：图表标题措辞、引用方式（如"如图X所示" vs "见图X"）
   - **过渡手法**：节与节之间的衔接句式
   - **数据呈现**：表格 vs 行内数据、精度、对比方式
   - **分析深度**：纯结果罗列 vs 结合理论解释 vs 与其他方法深入对比
2. **将格式特征写入 `thesis_state.md` 第1节**，持久保存

### Phase 3: 读取已写章节（如有新上传）
当用户上传了自己已写的第三章/第四章等前序章节时：
1. 通读已写章节，提取以下关键信息：
   - **术语定义表**：已定义的术语、缩写、符号
   - **核心方法命名**：如"预测模块""Scout层"等
   - **公式编号**：确认前序章节公式编号范围
   - **图表编号**：同上
   - **理论结论**：前序章节给出的关键结论和claim
   - **写作风格**：用户自己的行文习惯
2. **将提取信息写入 `thesis_state.md` 对应区块**（第2-6节）
3. 生成"前序章节摘要"，向用户确认

### Phase 4: 生成大纲
1. 根据目标小节，综合以下输入生成大纲：
   - 实验设计方案（experiment.md）
   - `thesis_state.md` 中的参考格式约束
   - `thesis_state.md` 中的理论Claim与实验对应表
2. 大纲包含：
   - 本节目的（1句话）
   - 段落结构（每段的核心论点）
   - 需要引用的图表编号
   - 需要读取的实验数据文件
   - 与前序章节的呼应点
3. 展示大纲，等待用户确认或修改

### Phase 5: 读取数据与素材
1. 读取对应的实验结果文件（JSON/日志）
2. 读取用户上传的前序章节中对应的理论内容
3. 提取关键数据点用于论文引用

### Phase 6: 逐节书写
1. 按大纲逐段生成论文内容
2. 书写时严格遵循：
   - `thesis_state.md` 中的参考格式特征
   - `thesis_state.md` 中的术语表和写作风格
   - 默认书写规范（见下方）
3. 每生成一节后暂停，等待用户反馈
4. 根据反馈修改后继续下一节
5. **用户反馈中的关键决策和偏好 → 写入 `thesis_state.md` 第8节**

### Phase 7: 整合与润色
1. 检查全章节过渡是否流畅
2. 统一术语和编号（依据 `thesis_state.md` 术语表）
3. 确认图表引用完整
4. 验证每个实验结论都能对应到Claim表
5. **更新 `thesis_state.md` 书写进度和编号范围**

## 书写规范

详细规范见 [writing_style.md](references/writing_style.md)，核心要点：
- **人称**：使用"本文"，不用"我们"
- **术语**：首次出现标注英文全称和缩写，如"困惑度（Perplexity, PPL）"
- **数据精度**：PPL 保留 2 位小数，Recall 保留 1 位小数（百分比）
- **图表**：图标题在下方，表标题在上方，编号为"图5.x"/"表5.x"
- **段落结构**：实验描述 → 结果展示（引用图表） → 分析讨论（归因 + 理论呼应）
